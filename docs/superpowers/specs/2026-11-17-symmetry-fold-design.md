# 대칭 영역 검토 설계 (2026-11-17)

## 1. 목적
조명 도면은 대칭인 경우가 많다. 대칭이면 일부 영역만 자세히 보고 전체 계산은 가능성 확인에만 써서 최적화를 빠르게 한다(사용자 요청).

## 2. 핵심 판단 — 도면을 자르지 말고, 대칭 칸을 합친다
지금 계산은 LED에서 광선을 쏘는 forward 방식이다. 이 방식에서는 도면을 잘라도 계산이 거의 빨라지지 않는다.

- **자를 때:** 반쪽만 계산하려면 자른 면에 거울 벽을 세우고 반쪽 LED만 쏴야 한다. 관측 칸 하나에 같은 노이즈를 얻는 데 필요한 광선 수는 전체를 쏜 뒤 대칭 칸끼리 합친 경우와 같다.
- **합칠 때:** 전체 도면을 그대로 계산하고 대칭인 관측 칸의 값을 합친다(접기). 칸마다 받는 광선이 대칭 개수만큼 늘어 노이즈가 그만큼 줄고, 목표 노이즈에 그만큼 일찍 닿는다.
  - 좌우 대칭: 약 2배 빠름
  - 좌우·폭 대칭: 약 4배 빠름
  - 링 LED 12개 회전 + 거울 대칭: 최대 약 24배 빠름
- **결론:** 도면·메시·광선 추적은 그대로 두고 집계(tally) 단계만 바꾼다. 끝 어두움 같은 끝 효과도 그대로 계산된다.
  - 곧은 라인 가운데의 반복 피치를 합치는 것은 하지 않는다. 길이 균일도 최저는 대개 양 끝인데 끝 칸은 합칠 짝이 없어, 반복을 합쳐도 판정이 빨라지지 않는다.

## 3. 대칭 종류
| 종류 | 조건 | 합치는 칸 |
|---|---|---|
| 길이 거울 | 열린 라인, 가운데 기준 좌우 대칭 | s ↔ L − s |
| 폭 거울 | 라인 중심선 기준 양쪽 대칭 | w ↔ −w |
| 회전(닫힌 라인) | 링, LED n개 같은 간격 | s ↔ s + L/n (n칸) |
| 회전 + 거울 | 위 조건에 더해 LED 사이 가운데도 거울 대칭 | 2n칸 |

## 4. 대칭 확인 — 두 단계, 하나라도 어긋나면 합치지 않음
1. **도면 검사(계산 전)**
   - LED 위치·방향: 대칭 짝이 0.25 mm 안에 있는지 확인한다.
   - 관측면 영역(raster mask): 접어서 겹치는지 확인한다.
   - 빛이 지나는 부품: 메시 점을 표본으로 뽑아 대칭 위치에서 가장 가까운 면까지 0.1 mm 안인지 확인하고, 소재·Milky·면 처리가 짝끼리 같은지 본다.
2. **결과 검사(계산 중)**
   - 처음 몇 묶음에서 짝 칸의 길이·폭 프로파일 차이를 노이즈와 비교한다. 노이즈의 3배를 넘는 차이가 이어지면 합치기를 끈다.
   - 끄면 화면에 "대칭 아님 — 전체 계산"이라고 표시한다. 몰래 끄지 않는다.

## 5. 어디에 쓰나
| 단계 | 대칭 합치기 | 이유 |
|---|---|---|
| 최적화 후보 빠른 검토(위치·형상·Milky) | 씀 | 같은 시간에 노이즈가 낮아 후보 순위가 정확해짐 |
| 진행 그래프·후보 값 | 씀(≈ 표시 그대로) | 위와 같음 |
| 광분포 시뮬레이션(④) | 씀(묻고 정함 — 7절 2번) | 목표 노이즈에 일찍 닿음 |
| 최종 판정(검증) | **안 씀 — 지금처럼 전체 영역** | 판정 숫자를 바꾸지 않음. 사용자가 말한 "큰 검토에서 가능성 확인"에 해당 |

## 6. 화면
- **2D 지도:** 합친 값을 펼쳐 전체 모양으로 보여 준다. 칸의 대칭 짝은 같은 값이다.
- **표시:** 시뮬레이션 상태 줄과 최적화 진행 줄에 "대칭 ½ 사용 · ×2 빠름"처럼 쓴다. 마우스를 올리면 어떤 대칭인지 설명한다.
- **켜고 끄기:** 설정 메뉴에 "대칭 영역 검토" 켜기/끄기를 둔다(기본 켜짐). 끄면 지금과 똑같이 동작한다.

## 7. 확인받을 것
1. 최종 판정은 지금처럼 전체 영역·접지 않은 값으로 둔다. 판정 숫자는 바뀌지 않는다.
2. 광분포 시뮬레이션(④)에도 합치기를 쓸지. 쓰면 빨라지지만, 노이즈가 줄어 최저/최고의 낮은 쪽 편향이 작아지므로 같은 도면의 균일도가 지금보다 조금 높게 나올 수 있다.
3. 기본값을 켜짐으로 할지.

## 8. 먼저 잴 것(구현 1단계, 결과 보고 후 진행)
- 평판 1열·링 예제에서 전체 계산과 접은 계산의 길이·폭 균일도 차이가 노이즈 안인지 잰다.
- 목표 노이즈까지 걸린 시간이 몇 배 줄었는지 잰다.
- 휜 확산판·모니터 링에서 도면 검사가 대칭/비대칭을 맞게 가려내는지 본다.

## 9. 고칠 파일(예상)
- `src/engine/mech3d/symmetry.js`(새 파일): 도면 검사, 짝 칸 표, 결과 검사
- `src/engine/mech3d/tally.js`: `foldAcc(G, acc, sym)` — 짝 칸 합치기·펼치기. `tallyStats` 는 접은 격자로 그대로 부름
- `src/ui/m3/progressive.js`, `src/engine/mech3d/autodesign.js`: 합치기 적용 위치(최종 판정 제외)
- 화면: 상태 줄 표시, 설정 메뉴 켜기/끄기
- 테스트: 대칭 판별(대칭·비대칭 도면), 접기·펼치기 왕복, 대칭 도면에서 접은 값 = 전체 값(노이즈 안), 최종 판정은 접지 않음
